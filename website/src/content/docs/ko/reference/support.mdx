PV17은 raw value 계약을 변경합니다. 정확한 DB 숫자는 string이고
IEEE-754 근사값은 number이며 JSON/temporal text 프로필은 parsed/native 편의
프로필과 구분됩니다. 마이그레이션은
`dccb69763e9e4a070280cf580d8f7b76368ec3d5`에서 시작했으며 최종 Runtime,
Docs, Release dry-run gate는 대기 중입니다. 인증 범위는 이후 gate에 기록한
정확한 프로필과 capability 조건뿐이며 DB/driver의 모든 버전이 아닙니다.
CI 성공은 package 발행을 의미하지 않습니다.

## 증거 label

- **Official** — 정확한 프로필에 무료 재현 환경과 릴리스 차단 real-engine 증거가 있습니다.
- **Conditional** — 이름이 지정된 조건에서만 증거가 적용됩니다.
- **Pending** — 해당 revision의 성공한 게이트가 아직 기록되지 않은 후보입니다.
- **Historical** — 정확한 revision 또는 과거 workflow가 조합을 실행했지만 현재 PV17 tree를 증명하지 않습니다.
- **Compatible** — 정확한 인증 대상이 없으며 더 넓은 host 또는 로컬 binding 검사는 통과할 수 있습니다.
- **Custom** — 사용자가 제공한 `QueryExecutor` 또는 `ConnectionProvider`입니다.
- **Unsupported** — 필요한 SQLBraid capability가 의도적으로 없습니다.

## SQLBraid Capability 증거 매트릭스 (SQL 문법 지원 목록이 아님)

Dialect, driver, runtime, server version은 별도 증거 축입니다. 검증된 taxonomy는
[`support/`](https://github.com/Clickin/SQLBraid/tree/main/support)에
기록하며 runtime은 이 파일을 읽지 않습니다. 대화형 매트릭스는 CI가 검사하는
동일한 기계 판독 대상, capability 조건, test ID의 정식 표시입니다. 변경된
표현 계약에 맞는 exact-SHA gate가 끝날 때까지 PV17 프로필 cell은 Pending입니다.
D1은 로컬 workerd binding을 통과했지만 managed SQLite 버전이 공개되지 않아
Compatible로 유지합니다.

숫자 capability cell은 semantics와 transport를 구분합니다.
`numeric.exact-integer`와 `numeric.exact-decimal`은 lossless/guarded 전송일
때만 string을 노출하고, `numeric.approximate-float`은 binary32 또는
binary64를 `number`로 노출하며, `numeric.bind-exact`는 별도의 입력 주장입니다.
`data.json-lossless-text`와 `data.json-parsed`를 합치지 않으며 native temporal
`Date`는 lossless 주장이 아닙니다. MERGE 반환 행은
`dml.merge-returning`, UPSERT/REPLACE/ON CONFLICT/ON DUPLICATE KEY 반환 행은
`dml.upsert-returning`입니다.

PV16의 DML-returning은 `sql.rows`와 materialized `db.execute`, `db.all`,
`db.one`, `db.maybeOne`만 지원 범위로 문서화합니다. SQLite RETURNING은
출력을 먼저 축적하고 SQL Server OUTPUT은 이후 실패 전에 행을 보낼 수 있으므로
`db.stream()`을 cross-driver 약속으로 만들지 않습니다.

`db.bulk(inputs, factory)`는 command-only, 하나의 shape × N values, 하나의
physical lease, 하나의 observer 작업입니다. 빈 입력은 acquire하지 않습니다.
Root bulk에는 portable transaction/auto-chunking 약속이 없고 driver는
`native-bulk`, `pipeline`, `prepared-loop`, `remote-batch` 중 실제 모드를
보고합니다.

첫 번째 파티 행 스트리밍 primitive는 dialect flag가 아닌 서로 다른
드라이버 capability입니다.

| 어댑터 | `db.stream()` primitive | 중요 경계 |
| --- | --- | --- |
| PostgreSQL / `pg` | `pg-cursor` | Optional peer이며 capability가 없으면 `BRAID_STREAM_UNSUPPORTED`입니다. |
| MySQL / `mysql2` | raw prepared `Execute.stream()` | prepared/binary 실행을 유지하고 lease 반환 전에 drain 또는 discard합니다. |
| MariaDB / Connector/Node.js | connector stream | `mysql2`에서 상속되지 않는 MariaDB driver capability입니다. |
| SQLite / `node:sqlite` | `StatementSync.iterate()` | native iterator 종료가 정리 경계입니다. |
| SQLite / `sqlite-wasm` | OO1 step/pull | 하나의 direct browser resource이며 충돌하는 root 작업은 거부합니다. |
| SQLite / Cloudflare D1 | 없음 | `BRAID_STREAM_UNSUPPORTED`; streaming을 흉내 내기 위해 paginate하지 않습니다. |
| Oracle Thin | `ResultSet` | 모든 ResultSet을 닫고 close 실패 시 lease를 폐기합니다. |
| SQL Server / Tedious | Request row event + bounded queue | lease 반환 전에 request가 완료되어야 합니다. |

Materialized `db.all()`은 의도적으로 버퍼링합니다. `db.call()`은 이질적인
result-set schema를 매핑하기 전에 루틴 result 리소스를 materialize하고
닫습니다. PostgreSQL refcursor 호출에는 기존 transaction이 필요합니다.
MySQL prepared CALL OUT/INOUT은 mysql2 3.x에 검증된 public carrier
discriminator가 없어 거부합니다. SQLite 루틴 호출은 지원하지 않으며 SQL
Server `CURSOR VARYING OUTPUT`은 애플리케이션 cursor 채널이 아닙니다.

## 릴리스 증거 출처

PV17의 최종 workflow run ID는 아직 없습니다. 아래의 과거 PV16 link는
provenance를 위해 보존하며 변경된 계약을 인증하지 않습니다.

- [Runtime portability: 34818111424](https://github.com/Clickin/SQLBraid/actions/runs/34818111424) — Node 22.18.0 릴리스 게이트와 packed Bun 1.3.14 / Deno 2.9.3 host 경로
- [Documentation site: 34818111252](https://github.com/Clickin/SQLBraid/actions/runs/34818111252) — 빌드와 링크 검사 통과, 배포 생략
- [Release dry-run: 34818113561](https://github.com/Clickin/SQLBraid/actions/runs/34818113561) — real-engine 게이트, immutable package/VSIX와 npm dry-run 통과, 실제 발행 생략

증거에는 검증한 구현 revision을 기록해야 합니다. 이후 revision은 자체 gate가
필요하며 역사 link가 임의 checkout을 인증하지는 않습니다. Node 24.21.0은
과거 전체 suite/finance 증거가 있지만 별도의 인증 대상은 아닙니다. Oracle
Free 23.9는 Oracle 19c나 Thick mode를 인증하지 않습니다. RC 발행에는
사용자 수락과 명시적인 릴리스 승인이 필요합니다.
