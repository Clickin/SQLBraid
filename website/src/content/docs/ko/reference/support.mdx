PV18은 PV17 raw-value 규칙을 유지하면서 profile 계약을 정교화합니다. 정확한 DB 숫자는 string이고
IEEE-754 근사값은 number이며 JSON/temporal text 프로필은 parsed/native 편의
프로필과 구분됩니다. Stage A 구현 revision은
`53db135bd156b6d65dc91785a671dec5249c95d4`입니다. 해당 revision의
[Runtime portability run 34851691821](https://github.com/Clickin/SQLBraid/actions/runs/34851691821),
[Documentation site run 34851706964](https://github.com/Clickin/SQLBraid/actions/runs/34851706964),
[Release dry-run 34851703042](https://github.com/Clickin/SQLBraid/actions/runs/34851703042)가
모두 통과했습니다. 아래의 여덟 exact tuple artifact는 기록된 프로필과
capability 조건에 따라 Stage A에서 Official입니다. 이후 revision에는 별도의
Stage B Runtime, Docs, Release exact-final SHA 검증이 필요하며 Stage B 완료나
package 발행은 주장하지 않습니다.

## 증거 label

- **Official** — 정확한 프로필에 무료 재현 환경과 릴리스 차단 real-engine 증거가 있습니다.
- **Conditional** — 이름이 지정된 조건에서만 증거가 적용됩니다.
- **Pending** — 해당 revision의 성공한 게이트가 아직 기록되지 않은 후보입니다.
- **Historical** — 정확한 revision 또는 과거 workflow가 조합을 실행했지만 현재 PV18 tree를 증명하지 않습니다.
- **Compatible** — 정확한 인증 대상이 없으며 더 넓은 host 또는 로컬 binding 검사는 통과할 수 있습니다.
- **Custom** — 사용자가 제공한 `QueryExecutor` 또는 `ConnectionProvider`입니다.
- **Unsupported** — 필요한 SQLBraid capability가 의도적으로 없습니다.

## SQLBraid Capability 증거 매트릭스 (SQL 문법 지원 목록이 아님)

Dialect, driver, runtime, server version은 별도 증거 축입니다. 검증된 taxonomy는
[`support/`](https://github.com/Clickin/SQLBraid/tree/main/support)에
기록하며 runtime은 이 파일을 읽지 않습니다. 대화형 매트릭스는 CI가 검사하는
동일한 기계 판독 대상, capability 조건, test ID의 정식 표시입니다. Stage A
기록에서 PG16.4, 범위를 지정한 PG18.6, MySQL 8.4.2, MariaDB 11.8.9,
Oracle Free 23.9, SQL Server 2022 CU18 Developer, Node SQLite 3.50.2,
browser WASM 3.53.4의 여덟 tuple artifact는
`exactTupleObserved=true`, `missingTests=[]`입니다. 이는 revision별 증거
기록입니다. 해당 exact 프로필은 Stage A에서 Official입니다. D1은 로컬
workerd binding을 통과했지만 managed SQLite 버전이 공개되지 않아
Compatible로 유지합니다.

숫자 capability cell은 semantics와 transport를 구분합니다.
`numeric.exact-integer`와 `numeric.exact-decimal`은 lossless/guarded 전송일
때만 string을 노출하고, `numeric.approximate-float`은 binary32 또는
binary64를 `number`로 노출하며, `numeric.bind-exact`는 별도의 입력 주장입니다.
`data.json-lossless-text`와 `data.json-parsed`를 합치지 않으며 native temporal
`Date`는 lossless 주장이 아닙니다. MERGE 반환 행은
`dml.merge-returning`, UPSERT/REPLACE/ON CONFLICT/ON DUPLICATE KEY 반환 행은
`dml.upsert-returning`입니다.

Support 항목은 driver raw 표현과 SQLBraid canonical 표현을 구분합니다. 정확한
string ID와 생성된 ID는 canonical decimal text이고 `affectedRows`, `rowCount`,
procedure status, bulk input count는 safe-range 운영 number입니다. capability
행이 count를 exact identity로 바꾸지는 않습니다.

PostgreSQL, mysql2, MariaDB profile descriptor는 `id`, `json`, `temporal`,
`typePolicy`, 정확한 connection option을 함께 가집니다. runtime과 codegen은
`typePolicyForProfile`을 재사용해야 합니다. native JSON root는 더 좁은 driver
계약이 증명되지 않으면 `unknown`이고, PostgreSQL native `time`/`timetz`는
text이며 `date`/`timestamp`/`timestamptz`는 `Date`입니다. option 하나를
바꾸면 별도 프로필이므로 다시 테스트하기 전에는 target 증거를 상속하지
않습니다.

Container 지원은 묵시적으로 재귀적이지 않습니다. array, domain,
range/multirange, composite, Oracle object/collection, SQL Server
`sql_variant`, vector, parsed JSON root에는 별도 증거가 필요합니다. 지원
container 행은 테스트한 transport만 설명하며 모든 nested member를 인증하지
않습니다.

지원 추가는 free-only 정책을 따릅니다. Official target에는 무료로 재현 가능한
CI 환경, 정확한 version/profile tuple, 기계 판독 manifest row, maintainer-safe
runtime cost가 필요합니다. 유료 환경은 자동으로 승격하지 않으며 contributor가
적합한 외부 CI 경로를 제공하고 유지해야 합니다.

역사적 PV16 증거는 `sql.rows`와 materialized `db.execute`, `db.all`,
`db.one`, `db.maybeOne`의 DML-returning을 다룹니다. SQLite RETURNING은
출력을 먼저 축적하고 SQL Server OUTPUT은 이후 실패 전에 행을 보낼 수 있으므로
`db.stream()`을 cross-driver 약속으로 만들지 않습니다. 이 capability의
Stage A 증거는 `53db135bd156b6d65dc91785a671dec5249c95d4` 구현 revision에
귀속되며 Runtime, Docs, Release 세 gate를 모두 통과했습니다. 이후 revision은
최종 인증 전에 별도 Stage B exact-final SHA 검증이 필요합니다.

`db.bulk(inputs, factory)`는 command-only, 하나의 shape × N values, 하나의
physical lease, 하나의 observer 작업입니다. 빈 입력은 acquire하지 않습니다.
Root bulk에는 portable transaction/auto-chunking 약속이 없고 driver는
`native-bulk`, `pipeline`, `prepared-loop`, `remote-batch` 중 실제 모드를
보고합니다.

첫 번째 파티 행 스트리밍 primitive는 dialect flag가 아닌 서로 다른
드라이버 capability입니다.

| 어댑터 | `db.stream()` primitive | 중요 경계 |
| --- | --- | --- |
| PostgreSQL / `pg` | `pg-cursor` | Optional peer이며 capability가 없으면 `BRAID_STREAM_UNSUPPORTED`입니다. |
| MySQL / `mysql2` | raw prepared `Execute.stream()` | prepared/binary 실행을 유지하고 lease 반환 전에 drain 또는 discard합니다. |
| MariaDB / Connector/Node.js | connector stream | `mysql2`에서 상속되지 않는 MariaDB driver capability입니다. |
| SQLite / `node:sqlite` | `StatementSync.iterate()` | native iterator 종료가 정리 경계입니다. |
| SQLite / `sqlite-wasm` | OO1 step/pull | 하나의 direct browser resource이며 충돌하는 root 작업은 거부합니다. |
| SQLite / Cloudflare D1 | 없음 | `BRAID_STREAM_UNSUPPORTED`; streaming을 흉내 내기 위해 paginate하지 않습니다. |
| Oracle Thin | `ResultSet` | 모든 ResultSet을 닫고 close 실패 시 lease를 폐기합니다. |
| SQL Server / Tedious | Request row event + bounded queue | lease 반환 전에 request가 완료되어야 합니다. |

Materialized `db.all()`은 의도적으로 버퍼링합니다. `db.call()`은 이질적인
result-set schema를 매핑하기 전에 루틴 result 리소스를 materialize하고
닫습니다. PostgreSQL refcursor 호출에는 기존 transaction이 필요합니다.
MySQL prepared CALL OUT/INOUT은 mysql2 3.x에 검증된 public carrier
discriminator가 없어 거부합니다. SQLite 루틴 호출은 지원하지 않으며 SQL
Server `CURSOR VARYING OUTPUT`은 애플리케이션 cursor 채널이 아닙니다.

## 릴리스 증거 출처

Stage A 증거는 구현 revision
`53db135bd156b6d65dc91785a671dec5249c95d4`에 귀속됩니다. Runtime
portability run
[34851691821](https://github.com/Clickin/SQLBraid/actions/runs/34851691821),
documentation site run
[34851706964](https://github.com/Clickin/SQLBraid/actions/runs/34851706964),
Release dry-run
[34851703042](https://github.com/Clickin/SQLBraid/actions/runs/34851703042)가
모두 통과했습니다. 나열한 여덟 exact 프로필은 Stage A에서 Official입니다.
이후 revision에는 세 gate를 통한 별도 Stage B exact-final SHA 검증이 필요하며
Stage B 완료나 package 발행은 주장하지 않습니다.

- [Runtime portability: 34818111424](https://github.com/Clickin/SQLBraid/actions/runs/34818111424) — Node 22.18.0 릴리스 게이트와 packed Bun 1.3.14 / Deno 2.9.3 host 경로
- [Documentation site: 34818111252](https://github.com/Clickin/SQLBraid/actions/runs/34818111252) — 빌드와 링크 검사 통과, 배포 생략
- [Release dry-run: 34818113561](https://github.com/Clickin/SQLBraid/actions/runs/34818113561) — real-engine 게이트, immutable package/VSIX와 npm dry-run 통과, 실제 발행 생략

증거에는 검증한 구현 revision을 기록해야 합니다. 이후 revision은 자체 세
gate가 필요하며 역사 link가 임의 checkout을 인증하지는 않습니다. Node 24.21.0은
과거 전체 suite/finance 증거가 있지만 별도의 인증 대상은 아닙니다. Oracle
Free 23.9는 Oracle 19c나 Thick mode를 인증하지 않습니다. RC 발행에는
사용자 수락과 명시적인 릴리스 승인이 필요합니다.
