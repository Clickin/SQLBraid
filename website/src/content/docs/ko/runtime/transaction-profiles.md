---
title: 향후 트랜잭션 프로필 아키텍처
description: 향후 격리/세션 API를 위해 예약된 개념적 경계이며 0.1.0 기능이 아닙니다.
---

:::caution 개념만 다룹니다
이 페이지의 내용은 기존 SQLBraid API가 아닙니다. 0.1.0 팩토리에 `isolation`, `transactionProfile` 또는 유사한 옵션을 전달하지 마세요. 의도적으로 허용되지 않습니다.
:::

SQLBraid는 이미 네 가지 관심사를 분리합니다.

1. **Dialect** — SQL 표면, placeholder, 인용, 기본 데이터베이스 의미.
2. **Driver** — 프로토콜 브리지와 결과 정규화(`pg`, `mysql2`, `node:sqlite`).
3. **실행 런타임** — 물리적 lease 소유, 트랜잭션 고정, savepoint, Node/Bun/Deno에서의 범위.
4. **트랜잭션 프로필** — 격리/세션 동작을 명시적으로 설명하기 위한 향후 개념.

향후 프로필은 dialect나 드라이버 이름이 그러한 동작을 암시하지 않도록 지원되는 격리/세션 작업과 증거를 설명할 수 있습니다. 이 설계에서는 데이터베이스 기본값, 풀 lease 설정, savepoint 동작, 실패/오염, 사용자 지정 드라이버를 통한 PostgreSQL dialect 같은 조합을 고려해야 합니다.

0.1.0에서 실용적인 규칙은 더 단순합니다. `db.tx`는 물리적 연결 하나를 고정하고, 그 외에는 격리를 데이터베이스/드라이버 기본값에 맡깁니다. 명시적 격리 설정은 선택한 데이터베이스의 순서와 물리적 연결 규칙을 따라야 합니다. [트랜잭션 격리 기본값](/SQLBraid/runtime/transactions/#격리-기본값)을 참고하세요. 이 개념 페이지를 프로필 객체, 팩토리 옵션 또는 dialect 간 격리 추상화가 출시되었다는 약속으로 해석하지 마세요.
