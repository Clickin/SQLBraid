## Evidence labels

- **Official** — an exact profile has zero-cost reproduction and release-blocking real-engine evidence.
- **Conditional** — the evidence applies under the named condition.
- **Pending** — a candidate has no recorded successful gate for the stated revision.
- **Historical** — an exact revision or old workflow exercised a combination; it does not prove the current PV18 tree.
- **Compatible** — no exact certified target; broader host or local-binding checks may still pass.
- **Custom** — a user-provided `QueryExecutor` or `ConnectionProvider`.
- **Unsupported** — the required SQLBraid capability is intentionally absent.

## Capability evidence matrix

Dialect, driver, runtime, and server version are separate evidence axes. The
verified taxonomy is recorded in
[`support/`](https://github.com/Clickin/SQLBraid/tree/main/support);
the runtime does not read these files. The interactive matrix is the canonical
rendering of the same machine-readable targets, capability conditions and test
IDs enforced by CI. Stage A records `exactTupleObserved=true` and
`missingTests=[]` for PG16.4, scoped PG18.6, MySQL 8.4.2, MariaDB 11.8.9,
Oracle Free 23.9, SQL Server 2022 CU18 Developer, Node SQLite 3.50.2, and
browser WASM 3.53.4. These exact profiles are Official for Stage A and remain
revision-specific. D1 remains Compatible: its local workerd binding passes, but
the managed SQLite version is unreported.

Numeric capability cells distinguish exact semantics from transport:
`numeric.exact-integer` and `numeric.exact-decimal` expose strings only when
transport is lossless/guarded; `numeric.approximate-float` exposes binary32 or
binary64 as `number`; `numeric.bind-exact` is a separate input claim.
`data.json-lossless-text` and `data.json-parsed` must not be conflated, and
temporal native `Date` is not a lossless claim. MERGE returned rows use
`dml.merge-returning`; UPSERT/REPLACE/ON CONFLICT/ON DUPLICATE KEY returned rows
use `dml.upsert-returning`.

Support entries distinguish driver raw representation from SQLBraid canonical
representation. An exact string ID or generated ID is canonical decimal text;
`affectedRows`, `rowCount`, procedure status, and bulk input counts are
operational safe-range numbers. A green capability row never turns one of
those counts into an exact identity claim.

PostgreSQL, mysql2, and MariaDB profile descriptors pair `id`, `json`,
`temporal`, `typePolicy`, and exact connection options. `typePolicyForProfile`
is the reuse point for runtime and codegen. Native JSON roots use `unknown`
unless a narrower driver contract is proven; native PostgreSQL `time` and
`timetz` remain text while `date`, `timestamp`, and `timestamptz` use `Date`.
Changing one option creates a different profile and invalidates the target
evidence until retested.

Container support is not recursive by implication. Arrays, domains, ranges,
multiranges, composites, Oracle objects/collections, SQL Server `sql_variant`,
vectors, and parsed JSON roots require container-specific evidence. A supported
container row describes the tested transport only; it does not certify every
nested member.

Support additions follow the free-only policy: an Official target needs a
zero-cost reproducible CI environment, an exact version/profile tuple, a
machine-readable manifest row, and maintainer-safe runtime cost. A proprietary
or paid environment is not promoted automatically; its contributor must
provide and maintain an acceptable external CI path.

Historical PV16 evidence covers materialized DML-returning through `db.execute`,
`db.all`, `db.one`, and `db.maybeOne` with `sql.rows`. It does not make
`db.stream(sql.rows\`... RETURNING/OUTPUT ...\`)` a cross-driver support claim:
SQLite buffers RETURNING output, and SQL Server can emit OUTPUT rows before a
later statement failure. MySQL's absence of a generic clause is a server fact,
not a SQLBraid rewrite opportunity. Stage A evidence for implementation revision
`53db135bd156b6d65dc91785a671dec5249c95d4` covers the current capability
records; all three Stage A Runtime, Docs, and Release gates passed. Any later
revision requires separate Stage B exact-final SHA verification before final
certification.

`db.bulk(inputs, factory)` is command-only, one shape × N values, one physical
lease, and one bulk observer operation. Empty input performs no acquire.
Drivers validate shape/cardinality/hints before I/O and report
`native-bulk`, `pipeline`, `prepared-loop`, or `remote-batch`. Root bulk has no
portable transaction or auto-chunking promise; use `db.tx()` for callback
atomicity.

First-party row-streaming primitives are implemented as distinct driver
capabilities, not dialect flags:

| Adapter | `db.stream()` primitive | Important boundary |
| --- | --- | --- |
| PostgreSQL / `pg` | `pg-cursor` | Optional peer; missing capability yields `BRAID_STREAM_UNSUPPORTED`. |
| MySQL / `mysql2` | raw prepared `Execute.stream()` | Preserve prepared/binary execution; drain or discard before lease release. |
| MariaDB / Connector/Node.js | connector stream | MariaDB driver capability; not inherited by `mysql2`. |
| SQLite / `node:sqlite` | `StatementSync.iterate()` | Native iterator termination is the cleanup boundary. |
| SQLite / `sqlite-wasm` | OO1 step/pull | One direct browser resource; conflicting root operations reject. |
| SQLite / Cloudflare D1 | None | `BRAID_STREAM_UNSUPPORTED`; do not paginate to simulate streaming. |
| Oracle Thin | `ResultSet` | Close every ResultSet; close failure discards the lease. |
| SQL Server / Tedious | Request row events + bounded queue | Request completion precedes lease release. |

Materialized `db.all()` is intentionally buffered. `db.call()` materializes
and closes routine result resources before mapping heterogeneous result-set
schemas. PostgreSQL refcursor calls require an existing transaction; MySQL
prepared CALL OUT/INOUT is rejected because mysql2 3.x exposes no proven public
carrier discriminator; SQLite routine calls remain unsupported; SQL Server
`CURSOR VARYING OUTPUT` is not an application cursor channel.
