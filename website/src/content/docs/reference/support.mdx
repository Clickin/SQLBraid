Support labels mean:

- **Official** — exercised in the SQLBraid release gate for that runtime/driver combination.
- **Compatible** — expected from public APIs and checked locally, but not a release-gate claim.
- **Custom** — connected through `QueryExecutor` or `ConnectionProvider` rather than a first-party adapter.
- **Unsupported** — a required capability is absent, or the combination has explicitly failed checks.

The matrix is evidence, not a promise inferred from a package existing. In particular, an adapter is not Official until a real database check is part of the release gate.

| Runtime/library | Status | Evidence |
| --- | --- | --- |
| Node 22.18.0 + core/template/runtime | Official | Release gate target |
| Node 24.21.0 + core/template/runtime | Compatible | Local packed smoke, not a CI gate |
| Bun 1.3.14 + core/template/runtime | Official | Packed portability smoke |
| Deno 2.9.3 + core/template/runtime | Official | Packed portability smoke |

| Adapter or integration | Node 22.18.0 | Node 24.21.0 | Bun 1.3.14 | Deno 2.9.3 |
| --- | --- | --- | --- | --- |
| PostgreSQL / `pg` 8.23.0 | Official | Compatible | Official | Official |
| MySQL / `mysql2` 3.24.4 | Official | Compatible | Official | Official |
| SQLite / `node:sqlite` | Official | Compatible | Unsupported | Official |
| Oracle portable root / `@sqlbraid/oracle` | Official | Compatible | Official | Official |
| Oracle Thin / `node-oracledb` 7.0.1 | Official | Compatible | Unsupported | Unsupported |
| SQL Server portable root / `@sqlbraid/mssql` | Official | Compatible | Official | Official |
| SQL Server / Tedious 20.0.0 | Official | Compatible | Unsupported | Unsupported |
| Other driver or database | Custom | Custom | Custom | Custom |

Oracle targets `node-oracledb` Thin mode; Thick mode is not Official. SQL Server targets the Tedious adapter. The Oracle `call()` path and SQL Server OUT/return-value routine binding are Unsupported in this RC. PostgreSQL, MySQL, and SQLite explicitly reject parameter hints rather than silently ignoring them.

## PV14 transport map (verification pending)

All five first-party adapters receive the same logical `RenderedStatement` and
materialize their own request after pure binding description:

| Path | Transport | Effective reuse policy |
| --- | --- | --- |
| PostgreSQL / `pg` | text-positional `$1..$N` | fresh unnamed simple, driver-owned |
| MySQL / `mysql2` | text-positional `?` | driver-owned reuse |
| SQLite / `node:sqlite` | documented `DatabaseSync.prepare(text)` with `?` | fresh simple, driver-owned |
| Oracle Thin / `node-oracledb` | text-positional `:1..:N` with descriptors | driver cache reuse |
| SQL Server / Tedious | typed request `@p1..@pN` with `TYPES.*` | fresh Request/`execSql`, simple |

Requested reuse is policy input, not evidence of effective reuse; the adapter
reports the effective result. Placeholder syntax does not participate in
logical prepared shape identity.

Dialect, driver, execution runtime, and transaction profile are separate axes. The [successful PV13 runtime gate at d4bc626](https://github.com/Clickin/SQLBraid/actions/runs/34753809318) exercises Oracle 23.9.0.25.07 Thin and SQL Server 2022 CU18 (16.0.4185.3) with Node 22.18.0 on Linux x64. Local SQL Server ARM emulation does not establish Official ARM support. Bun/Deno driver subpaths and Oracle Thick mode are not covered; all five portable roots pass separately on the pinned Node/Bun/Deno versions.
