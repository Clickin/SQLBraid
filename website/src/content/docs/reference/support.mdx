## Evidence labels

- **Official** — an exact profile has zero-cost reproduction and release-blocking real-engine evidence.
- **Conditional** — the evidence applies under the named condition.
- **Pending** — a candidate has no recorded successful gate for the stated revision.
- **Historical** — an exact revision or old workflow exercised a combination; it does not prove the current PV16 tree.
- **Compatible** — no exact certified target; broader host or local-binding checks may still pass.
- **Custom** — a user-provided `QueryExecutor` or `ConnectionProvider`.
- **Unsupported** — the required SQLBraid capability is intentionally absent.

## Capability evidence matrix

Dialect, driver, runtime, and server version are separate evidence axes. The
verified taxonomy is recorded in
[`support/`](https://github.com/Clickin/SQLBraid/tree/main/support);
the runtime does not read these files. The interactive matrix is the canonical
rendering of the same machine-readable targets, capability conditions and test
IDs enforced by CI. Eight exact profiles are certified. D1 remains Compatible:
its local workerd binding passes, but the managed SQLite version is unreported.

PV16 supports materialized DML-returning through `db.execute`, `db.all`,
`db.one`, and `db.maybeOne` with `sql.rows`. It does not make
`db.stream(sql.rows\`... RETURNING/OUTPUT ...\`)` a cross-driver support claim:
SQLite buffers RETURNING output, and SQL Server can emit OUTPUT rows before a
later statement failure. MySQL's absence of a generic clause is a server fact,
not a SQLBraid rewrite opportunity.

`db.bulk(inputs, factory)` is command-only, one shape × N values, one physical
lease, and one bulk observer operation. Empty input performs no acquire.
Drivers validate shape/cardinality/hints before I/O and report
`native-bulk`, `pipeline`, `prepared-loop`, or `remote-batch`. Root bulk has no
portable transaction or auto-chunking promise; use `db.tx()` for callback
atomicity.

First-party row-streaming primitives are implemented as distinct driver
capabilities, not dialect flags:

| Adapter | `db.stream()` primitive | Important boundary |
| --- | --- | --- |
| PostgreSQL / `pg` | `pg-cursor` | Optional peer; missing capability yields `BRAID_STREAM_UNSUPPORTED`. |
| MySQL / `mysql2` | raw prepared `Execute.stream()` | Preserve prepared/binary execution; drain or discard before lease release. |
| MariaDB / Connector/Node.js | connector stream | MariaDB driver capability; not inherited by `mysql2`. |
| SQLite / `node:sqlite` | `StatementSync.iterate()` | Native iterator termination is the cleanup boundary. |
| SQLite / `sqlite-wasm` | OO1 step/pull | One direct browser resource; conflicting root operations reject. |
| SQLite / Cloudflare D1 | None | `BRAID_STREAM_UNSUPPORTED`; do not paginate to simulate streaming. |
| Oracle Thin | `ResultSet` | Close every ResultSet; close failure discards the lease. |
| SQL Server / Tedious | Request row events + bounded queue | Request completion precedes lease release. |

Materialized `db.all()` is intentionally buffered. `db.call()` materializes
and closes routine result resources before mapping heterogeneous result-set
schemas. PostgreSQL refcursor calls require an existing transaction; MySQL
prepared CALL OUT/INOUT is rejected because mysql2 3.x exposes no proven public
carrier discriminator; SQLite routine calls remain unsupported; SQL Server
`CURSOR VARYING OUTPUT` is not an application cursor channel.
