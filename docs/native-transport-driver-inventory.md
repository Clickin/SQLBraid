# First-party adapter transport inventory

This is a post-native-transport snapshot for future driver adoption work. It records public binding surfaces without promoting any additional adapter to `native-value-template`.

| Driver adapter | Public native tagged/value-template API? | Public prepared binding API? | Current SQLBraid transport | Candidate future transport | Blocking semantic mismatch | Evidence |
| --- | --- | --- | --- | --- | --- | --- |
| `pg` via `@sqlbraid/postgres` | No; `pg.Client.query` accepts text/config objects, not a value-template tag | Yes; named prepared statements through query config | `text-positional ($1..$N)` | Keep text-positional unless a future adapter-specific API is added | No public tagged carrier; cursor, routine, and result mapping already depend on query/config APIs | [`packages/postgres/src`](../packages/postgres/src/index.ts), [`support/targets/postgres.json`](../support/targets/postgres.json), [node-postgres prepared statements](https://node-postgres.com/features/queries#prepared-statements) |
| `mysql2` via `@sqlbraid/mysql` | No; `Connection.execute`/`prepare` use SQL text plus values | Yes; `execute` and prepared statements | `text-positional (?)` | Keep text-positional | No public value-template tag; named/typed transport and stream APIs are driver-specific | [`packages/mysql/src`](../packages/mysql/src/index.ts), [`support/targets/mysql.json`](../support/targets/mysql.json), [mysql2 prepared statements](https://sidorares.github.io/node-mysql2/docs/examples/queries/prepared-statements) |
| MariaDB Connector/Node.js via `@sqlbraid/mariadb` | No; promise connection methods use SQL text plus values | Yes; `execute` and connector batch APIs | `text-positional (?)` | Keep text-positional with connector-native bulk where applicable | No public value-template tag; connector batch and stream carriers are driver-specific | [`packages/mariadb/src`](../packages/mariadb/src/index.ts), [`support/targets/mariadb.json`](../support/targets/mariadb.json), [MariaDB Connector execute](https://mariadb.com/kb/en/mariadb-connector-nodejs-promise-api/#execute) |
| Node `node:sqlite` via `@sqlbraid/sqlite/node-sqlite` | No; `DatabaseSync.prepare` returns statements but is not a tagged-template API | Yes; `StatementSync` bind/all/get/run methods | `text-positional (?NNN)` | Keep text-positional | Native statements are object methods, not a template carrier; iteration owns statement lifetime | [`packages/sqlite/src/node-sqlite.ts`](../packages/sqlite/src/node-sqlite.ts), [`support/targets/sqlite.json`](../support/targets/sqlite.json), [Node SQLite API](https://nodejs.org/api/sqlite.html) |
| `better-sqlite3` via `@sqlbraid/sqlite/better-sqlite3` | No; `Database#prepare` returns statements but is not a tagged-template API | Yes; prepared statement `all`/`run` methods | `text-positional (?)` | Keep text-positional | Synchronous calls block the JavaScript event loop; statement-local `safeIntegers(true)` and `iterate()` own exact reads and stream cleanup | [`packages/sqlite/src/better-sqlite3.ts`](../packages/sqlite/src/better-sqlite3.ts), [better-sqlite3 API](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md) |
| libSQL via `@sqlbraid/sqlite/libsql` | No; `@libsql/client` exposes `execute`/`batch`, not a tagged-template API | Yes; prepared SQL statement objects and bound args | `text-positional (?)` | Keep text-positional | Exact integers require explicit `intMode: "string"`; interactive Transaction handles provide continuity, while ordinary calls do not prove pinned sessions; no incremental cursor/stream API | [`packages/sqlite/src/libsql.ts`](../packages/sqlite/src/libsql.ts), [`support/targets/libsql.json`](../support/targets/libsql.json), [libSQL client API](https://github.com/tursodatabase/libsql-client-ts) |
| SQLite WASM OO1 via `@sqlbraid/sqlite/wasm` | No; OO1 exposes `prepare`/`bind`/`step`, not a tagged-template API | Yes; prepared OO1 statements | `OO1 prepare/bind/step` | Keep OO1 prepare/bind/step | WASM statement handles and C API result ownership cannot be represented by a generic template tag | [`packages/sqlite/src/wasm.ts`](../packages/sqlite/src/wasm.ts), [`support/targets/sqlite-wasm.json`](../support/targets/sqlite-wasm.json), [SQLite WASM OO1 API](https://sqlite.org/wasm/doc/trunk/api-oo1.md) |
| Cloudflare D1 via `@sqlbraid/sqlite/d1` | No; D1 exposes `prepare().bind()`, not a tagged-template API | Yes; D1 prepared statements | `ordered placeholders and D1 prepared binds` | Keep D1 prepared binds | Worker result and binding contracts are fixed by the D1 API; no native template carrier | [`packages/sqlite/src/d1.ts`](../packages/sqlite/src/d1.ts), [`support/targets/d1.json`](../support/targets/d1.json), [D1 prepare/bind](https://developers.cloudflare.com/d1/worker-api/d1-database/#prepare) |
| node-oracledb Thin via `@sqlbraid/oracle` | No; `connection.execute`/`executeMany` use SQL text and bind definitions | Yes; execute, executeMany, and typed bind definitions | `text-positional (:1..:N)` | Keep text-positional/typed request | Oracle OUT/INOUT, LOB, cursor, and type-hint semantics require driver bind definitions | [`packages/oracle/src`](../packages/oracle/src/index.ts), [`support/targets/oracle.json`](../support/targets/oracle.json), [node-oracledb bind variables](https://node-oracledb.readthedocs.io/en/latest/user_guide/bind.html) |
| Tedious via `@sqlbraid/mssql` | No; `Request.addParameter`/`addOutputParameter` use typed request objects | Yes; request parameter definitions | `typed request (@p1..@pN)` | Keep typed request | SQL Server OUTPUT/RETURN and precision/scale behavior require request metadata, not a string template | [`packages/mssql/src`](../packages/mssql/src/index.ts), [`support/targets/mssql.json`](../support/targets/mssql.json), [Tedious parameters](https://tediousjs.github.io/tedious/parameters.html) |
| Bun.SQL via `@sqlbraid/bun-sql` | Yes; callable `Bun.SQL` value-template API | Bun owns preparation behind the callable API; SQLBraid preserves template identity where possible | `native-value-template` | Already implemented; future work is version/profile-specific conformance | Bun structural helper values must be rejected at the SQLBraid value boundary; routines/streaming remain explicit capabilities | [`packages/bun-sql/src`](../packages/bun-sql/src/index.ts), [`support/targets/bun-sql-postgres.json`](../support/targets/bun-sql-postgres.json), [Bun SQL](https://bun.sh/docs/api/sql) |

The table describes API shape and current adapter evidence only. It does not infer runtime support from a host runtime or treat a generic prepared API as a native tagged-template transport.
