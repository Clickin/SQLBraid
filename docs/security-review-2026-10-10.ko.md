## SB-RT-2026-10-10-01 상세

### 원인

기존 Vite 플러그인은 HTTP 경로를 프로젝트 루트 또는 `/@fs/` 경로로 해석했습니다.
Vite는 별도로 `publicDir`의 파일도 같은 URL 공간에서 제공합니다.
따라서 `/leak/V1__private.sql` 요청의 검사 경로와 실제 제공 경로가 달랐습니다.

기존 `configResolved()` 검사는 마이그레이션 폴더 자체가 공개 폴더 안에 있는지만 확인했습니다.
공개 폴더 아래의 링크를 검사하지 않았습니다.
Vite의 클라이언트 빌드는 링크가 가리키는 SQL도 공개 자산으로 복사했습니다.

### 재현

임시 프로젝트를 다음과 같이 구성했습니다.

```text
project/
  migrations/
    V1__private.sql
  public/
    leak -> ../migrations
    leak.sql -> ../migrations/V1__private.sql
```

테스트 파일의 내용은 `SELECT 'security_test_marker';`였습니다.
플러그인을 활성화한 Vite 서버에서 다음 응답을 얻었습니다.

| 요청                        | 수정 전 결과                                    |
| --------------------------- | ----------------------------------------------- |
| `GET /leak/V1__private.sql` | HTTP 200, 테스트 SQL 본문                       |
| `GET /leak.sql`             | HTTP 200, 테스트 SQL 본문                       |
| 일반 클라이언트 빌드        | `dist/leak/V1__private.sql` 생성, 원본 SQL 포함 |

서버는 `127.0.0.1`에서만 열었습니다. 임시 프로젝트는 재현 후 삭제했습니다.
별도의 외부 서버나 실제 사용자 데이터를 사용하지 않았습니다.

### 수정

[vite.ts](../packages/migrate/src/vite.ts)에 다음 검사를 추가했습니다.

1. `configResolved()`에서 공개 폴더의 하위 디렉터리와 심볼릭 링크를 검사합니다.
2. 링크가 마이그레이션 디렉터리나 파일을 노출하면 서버 시작과 빌드를 거부합니다.
3. 방문한 실제 경로를 기록하여 같은 디렉터리를 반복 탐색하지 않습니다.
4. HTTP 요청마다 프로젝트 경로와 공개 자산 경로를 함께 검사합니다.

[회귀 테스트](../tests/migrate-vite-ssr.test.ts)는 디렉터리·파일·상위 폴더 링크를 각각 검사합니다.
서버 시작 뒤 공개 파일을 링크로 교체하는 경우도 검사합니다.
사용자 지정 `publicDir`, `/app/` 기본 경로, `?raw` 요청을 포함합니다.
정상 공개 파일과 링크, 기존 서버 전용 마이그레이션 동작도 유지되는지 확인합니다.

[패키지 README](../packages/migrate/README.md)의 차단 범위도 수정했습니다.
런타임 SQL 실행 API, 설정 형식, 의존성은 변경하지 않았습니다.

### 적용 시 주의점

이미 생성한 클라이언트 산출물은 이 수정으로 삭제되지 않습니다.
해당 링크 구성을 사용했다면 산출물을 다시 만들고 기존 공개 SQL을 제거해야 합니다.
실제 비밀정보가 들어 있었다면 노출 범위와 캐시를 별도로 확인해야 합니다.

공개 폴더 검사는 시작 시 파일 탐색 비용을 추가합니다.
보호 대상 링크를 사용하던 프로젝트는 시작 또는 빌드 오류를 받습니다.
SQL 파일을 공개 자산에서 제거하면 됩니다.

이 검사는 로컬 파일을 변경할 권한이 있는 공격자를 격리하는 샌드박스가 아닙니다.
마이그레이션 내용을 다른 이름으로 복사하거나 서버 번들 자체를 공개하는 배포까지 막지는 않습니다.

## 유지되는 신뢰 경계

- `sql.raw()`에는 신뢰할 수 있는 SQL만 전달해야 합니다. 임의 SQL을 허용하는 의도된 API입니다.
- CLI와 LSP의 설정 파일은 실행 가능한 코드입니다. 신뢰하지 않는 저장소에서 실행하면 안 됩니다.
- VS Code 확장은 [untrustedWorkspaces](../extensions/vscode/package.json)를 지원하지 않는다고 명시합니다. 다른 LSP 클라이언트의 신뢰 판단을 대신하지 않습니다.
- 마이그레이션 파일과 manifest는 검토한 배포 입력이어야 합니다. checksum 형식 검사만으로 작성자나 내용의 진위를 보증할 수 없습니다.
- SQLBraid의 풀은 애플리케이션이 임의로 바꾼 세션 상태를 모두 초기화하지 않습니다. 테넌트별 권한을 세션에 남기는 설계는 별도로 검토해야 합니다.
- 옵저버와 검증 오류에는 원본 값이 포함될 수 있습니다. 오류 객체 전체를 외부 로그에 기록하는 정책은 애플리케이션이 정해야 합니다.

이 항목들은 이번 작업에서 새로 확인한 취약점으로 집계하지 않았습니다.
동작을 바꾸려면 설정 실행, 세션 관리, 배포 모델의 호환성 검토가 필요합니다.
