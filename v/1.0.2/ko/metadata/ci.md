# CI에서 codegen --check 실행하기

> 생성된 모델을 항상 최신으로 유지합니다. 파생 파일을 직접 고치지 마세요.

생성된 모델은 파생 결과물입니다. 메타데이터 스냅샷이나 설정을 바꾸고, codegen을 실행하고, 출력이 최신인지는 CI가 최종 판단하게 하세요.

이 명령을 실행하기 전에 선택 사항인 CLI를 설치하세요.

```bash
npm install --save-dev @sqlbraid/cli
```

```bash
sqlbraid codegen
sqlbraid codegen --check
```

출력이 오래되었거나 없으면 CI가 실패합니다. 메타데이터나 설정을 바꾼 뒤, 그리고 패키징 전에 검사를 실행하세요. 빌드 시스템이 대상별 상태를 기계가 읽을 수 있는 형식으로 받아야 하면 `--json`을 쓰세요.

CLI는 출력을 쓰기 전에 선택한 대상을 모두 검증합니다. 그래서 정상인 대상 하나가 다른 대상의 잘못된 스냅샷이나 타입 정책을 가리지 못합니다. CLI는 최종 Row, Insert, Update 이름이 서로 겹치는지도 전역으로 검사합니다. Windows에서는 출력 충돌 키의 대소문자를 구분하지 않습니다.

생성된 선언을 직접 고치지 마세요. 모델이 틀렸다면 인스펙터 근거, 선택한 TypePolicy, 필터, 이름 규칙, 재정의 중 원인을 고친 뒤 다시 생성하세요. codegen은 임의의 `SELECT`나 `JOIN` 결과를 추론하지 않습니다. 그런 행 타입은 쿼리를 쓰는 곳에서 선언하세요.

CI는 런타임과 같은 표현 방식 프로필을 골라야 합니다. JSON, 날짜·시간, 숫자 옵션이 바뀌면 다른 프로필이며, 고유한 TypePolicy 출처와 근거가 필요합니다. 최신성 검사가 통과했다고 해서 그런 불일치가 괜찮다는 뜻은 아닙니다.
